# The TuxGuitar plugin: design

TuxGuitar is the free tablature editor OxiGuitar takes as its functional starting point. This plugin (#223 and #171 in github.com/mateusrdp/oxiguitar) reads and writes TuxGuitar's own files (`.tg`), so a TuxGuitar user's songs open in OxiGuitar and OxiGuitar's open in TuxGuitar. It is the last of the format plugins planned before v1.0 (MuseScore and ABC were dropped on 9 Nov 2026).

Status: built (session 39, 9 Nov 2026): the reader, the writer, their tests and the workflows. Not released yet.

## Decided

- **Only the latest form** (Mateus, 9 Nov 2026): the ZIP-and-XML `.tg` of TuxGuitar 2.x, read and written, in one plugin. TuxGuitar is open source and free, so no one needs an old form: TuxGuitar 2.x still opens every older `.tg` (0.7 to 1.5, through its compatibility readers) and saves it as 2.x. The binary `.tg` of TuxGuitar 0.7 to 1.5 is not read; such a file gets OxiGuitar's usual "not recognised" message, and the README says to open it in TuxGuitar 2 and save it. The cost: TuxGuitar 1.x (Debian still ships 1.6.6) can't open what this plugin writes.
- **No library**: there is no Rust library for `.tg`, so the reader and writer are our own code, ported from TuxGuitar's Java (`common/TuxGuitar-lib/.../io/tg/`, `TGStream`, `TGSongReaderImpl` and `TGSongWriterImpl`, in github.com/helge17/tuxguitar). TuxGuitar is LGPL-2.1; code ported from it may go into this GPL-3.0-or-later plugin, with a notice in the files that hold it. Mateus's standing rule (9 Nov 2026): always delegate to a mature existing library when one exists and doesn't cause trouble; general crates do the rest here: **roxmltree** to read `content.xml`, **quick-xml** to write it, **zip** (no default features, `deflate-flate2-zlib-rs`, as the MusicXML plugin) for the container.
- **One plugin, one format** (`oxiguitar.tuxguitar`, file `tuxguitar.oxp`, format `tg`, extension `tg`, read and write).

## Recognising the files

Interface 1.7's tests suffice, so the plugin needs no core change:

- **2.x**: a ZIP holding `version.txt` and `content.xml`. A signature names one ZIP member, so `{"zip_member": "version.txt"}`, and the reader checks the rest. Other members are ignored (TuxGuitar refuses such a file, as its `invalidContent.tg` test shows; nothing in them would be read, so OxiGuitar reads the song). `version.txt` is one line, `TuxGuitar_file_format MAJOR.MINOR` (with or without a newline): major 2 is read, a newer minor is read with a note in the log (TuxGuitar does the same), another major is refused with a message naming the version.
- The binary 1.x form (a length byte, then `TuxGuitar File Format - 1.N` in UTF-16BE; 0.7 and 0.8 say `TG_DEVEL-…`) is not claimed.

## Reading

TuxGuitar's model follows Guitar Pro's, as OxiGuitar's does, so most of it maps one to one (`src/read.rs`). What each value means was checked in TuxGuitar's own code, not guessed:

- **Song**: name → title, artist, album, author → music, writer → words, copyright, transcriber, comments → notices (one a line), date → a last notice "Date: ...".
- **Channels** (`TGChannel`, shared by tracks): bank 128 is percussion; program, volume (0–127) and balance (0–127, 64 the middle) become the track's `Instrument` and `Mix`. Chorus, reverb, phaser and tremolo levels and TuxGuitar's channel parameters (its sound plugins' settings) have no place in OxiGuitar and are named as losses.
- **Measure headers** → master bars: time signature and tempo carry on until a header changes them; tempo is in any note value (`base`, `dotted`) and becomes quarters a minute, a change from the bar before a tempo change at the bar's start. TuxGuitar's `repeatClose` counts the times it goes back, OxiGuitar the times a section plays (close + 1). Alternatives are a bit set; markers keep their colour; triplet feel is eighths or sixteenths. A `lineBreak` starts a new line at its bar (`TGLayoutVertical`), so line breaks become Design Mode's bars per system (`Score::layout`).
- **Tracks**: name, colour, strings (highest first, as OxiGuitar's), solo/mute, maximum fret, lyrics (`from`, counted from 1, is the bar the line starts at). A positive `offset` is a capo (TuxGuitar's Guitar Pro importer puts Guitar Pro's capo there; a note sounds at string + offset + fret); a negative one, which OxiGuitar's capo can't be, tunes every string down by as much, with a note.
- **Clefs**: TuxGuitar writes treble and bass clefs an octave above sounding, as guitar and bass music is written (its `TGNotation` places real E4 in the space under the top line, written E5), so `treble` is OxiGuitar's `Treble8vb` and `bass` its `Bass8vb`; tenor and alto map to themselves; drums are `Neutral`.
- **Key signatures** are per track and measure in TuxGuitar (0–7 sharps, 8–14 one to seven flats), per bar in OxiGuitar: the first track's are kept, and a later track that differs is named.
- **Beats**: each has a precise start (TuxGuitar's whole note is 11,531,520 units, four times the least common multiple of a sixty-fourth and every tuplet it knows; a song starts a quarter in) and two voices with their own durations. A voice with no notes is empty unless it says `empty="false"` (then it is a rest), as TuxGuitar decides. Each voice becomes one of OxiGuitar's, its beats placed by their starts; a gap is filled with empty beats, a beat that starts inside the one before is left out. What the voices share (strum, pick stroke, chord diagram, text) goes on the first voice's beat there. Stem directions are named as lost.
- **Notes**: string and fret (drums: the pitch, string + fret + offset), tied notes, velocity (carried from note to note in a voice, 95 by default) → the nearest dynamic (TuxGuitar's eight levels are 15 to 127 in steps of 16; others are named), and the effects: vibrato, dead and ghost notes, slides (TuxGuitar has one kind: a shift slide), hammer-ons, accents (normal and heavy), palm mute, staccato, let ring, trills, tremolo picking. Tapping, slapping, popping, fade-in and the tremolo bar are the beat's in OxiGuitar. A bend's points are twelfths of the note and quarter tones (TuxGuitar reads a Guitar Pro bend's 25 units, 50 cents, as one); a tremolo bar's are semitones. Harmonics other than natural store an index into TuxGuitar's table (AH12, AH9, AH5, AH7, AH4, AH3: the frets above the note where the string is touched, and the semitones the harmonic sounds above it): an artificial harmonic becomes its semitones, a tapped one its touched fret. Grace notes become a grace beat before their beat, as the Guitar Pro reader does; their "bend" transition has no place and is named. The "alternative enharmonic" becomes the note's other name (`src/spell.rs`).
- Anything left out is named in the import log, as the other format plugins do.

## Writing

The 2.0 form as TuxGuitar 2 writes it (`src/write.rs`): `version.txt` (`TuxGuitar_file_format 2.0`) and `content.xml`, the reverse of reading, in TuxGuitar's element order and without indentation; what it writes validates against TuxGuitar's schema (`fixtures/tuxguitar/tuxguitar_20.xsd`). One channel a track. OxiGuitar's first two voices are merged into TuxGuitar's beats by their starts, a voice with nothing there written empty; every bar gets at least one beat, and the first bar one at its start (TuxGuitar refuses a file whose first beat doesn't start the song). Grace beats fold into the notes after them; what OxiGuitar keeps on a beat goes on each of its notes. Tempos are written in quarters, or in eighths where that makes a whole number. Losses, named before anything is written, for what `.tg` can't hold: voices past the second, staves past the first, the palette's marks of v0.17 (slurs, hairpins, ottavas, fermatas, pedal, wah, ornaments, rasgueado, golpe, pick scrapes, dead slaps, barres, slash notation, beaming, forced tuplet groups), navigation signs and jumps, tempo changes inside a bar and their texts, double bars, free time, section letters, a staff's transposition, fingerings, string numbers, slides into and out of notes, fade-outs and swells, whammy-bar vibrato, feedback harmonics, tuplets TuxGuitar doesn't have, a third dot, note values shorter than a sixty-fourth, lyrics past the first line. Simile bars are written out; wide vibrato and legato slides are written as TuxGuitar's one kind (named as notes).

## Tests

- **TuxGuitar's own test files** (`fixtures/tuxguitar/`, with their LGPL-2.1 `NOTICE`): `tests/tuxguitar_files.rs` checks what TuxGuitar's `TestFileFormat20.java` asserts of `test_20.xml` (hand-written, every element) and `reference_20.tg`, in OxiGuitar's terms; that `Untitled_extended_30.tg` (major 3), `noVersion.tg`, `invalidVersion.tg`, `notTuxGuitar.tg` and the 1.5 files are refused; that `Untitled_extended_21.tg` (minor 1) reads with a note; and that every other 2.x file reads. `tests/read_write.rs` writes each 2.x file and reads it back exactly, and validates what is written against TuxGuitar's schema with xmllint where it is installed (as on CI's Ubuntu).
- **Our own fixture**: the core's test song converted by the plugin (`fixtures/oxiguitar-test.tg`), read back exactly.
- **The private corpus**, locally (`tests/corpus.rs`, files in the ignored `corpus/files/`): every Guitar Pro file converted to `.tg` with `oxiguitar-cli convert`, compared with the original (`info`: tracks, notes, bars, bar check), then round-tripped: exact from the first trip where the writer names no losses, stable from the second otherwise.
- The contract suite (`tests/contract.rs`, which also checks that the signature claims 2.x files and not 1.x ones), and fuzz targets for reading and for writing (`fuzz/`). Before the first push, 26,000 mutated fixtures (bytes changed or cut, numbers and words in the XML replaced) went through read, write and read under `catch_unwind` in debug and release: no panic.
- Still wanted from Mateus: `.tg` files of his own, and a look at what the plugin writes in TuxGuitar 2.
